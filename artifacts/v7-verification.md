**语义与业务信息的人工结论**

在本次覆盖的渲染状态中，系统文字保留了对象、字段、数值、日期、状态和动作，没有发现需要依靠教程段落解释才能完成的已测关键步骤。授权屏保留孩子、行为或物品、金额、余额、原因或备注；购买屏保留单价×数量和余额等式；照料屏区分共享免费次数与库存来源；能力状态明确显示“共享／本机”“指令演示／AI 暂不可用”“未开启”等实际状态。

用户内容没有因含解释性词语而被删改。测试原因使用“请不要缩短这条用户事实：例如孩子自己整理了书包，还解释了水杯为什么放在侧袋。”；备注使用“这是用户填写的备注：请保留说明和例子，周六带蓝色水杯，再到图书馆一起阅读。”。两者经过表单、授权、记录或提醒保存链后仍保留原文。普通交付预览另外使用“自己把书包和水杯放好”，不把测试哨兵文字作为产品文案。

人工检查先发现并推动修复了两类真实呈现问题：DIY 输入 7 时摘要仍显示 +5；通用未知指令的旧解释文本包含“多少积分”，缩短时错误变成了“分值是多少？”。最终“你好”显示“指令未识别”，真正缺分值或原因时仍分别询问分值和具体原因。

同一条受控 AI 检查中附有 **19 个固定响应语义断言**，不是额外增加 19 项消费者检查：覆盖三种多指令文本、三种 1200 字限制路径、日期无效、不适用操作、动态名称中含 PIN 或“多少积分”、四种字段过长、两种服务失败、真正缺原因／分值，以及同名但不同价的礼品。全部用浏览器实际请求和真实 UI 渲染验证；HTTP 错误检查当前错误节点。两个同名礼品分别为 12 分和 30 分时，答复保留名称和可申请状态，不根据名称臆测其中一个价格。受控响应的完整原文及实际显示文字保存在 [完整消费者结果](v7-browser-results.json)的 `semanticResponses` 字段。

19 个语义边界使用隔离的响应夹具，不代表访问了真实外部模型。常规的 AI 填写、余额／礼品查询和未知问候则使用实际本地解析链；迟到结果检查实际触发请求后再修改手工内容或切换面板，确保旧响应不覆盖当前输入。

**离线与客户端**

最终 HTML 在 `file:` 和本地 HTTP 下均执行：首次 PIN 设置、两次输入不一致、返回修改、设置后保存 +5、重新载入仍保留记录；使用旧 PIN 将本机方式改为算术题，显示题目并取消加分；执行本地礼品查询。两种方式均无 API 请求、无额外外部请求、无脚本错误。这里的算术题检查是显示与取消，没有把它写成成功提交算术答案的新增证明。

C1–C8 使用未修改的 [客户端测试](../test/client.test.cjs)，通过 `FAMILY_EVIDENCE_VERSION=v7` 写入新证据，最终耗时 28.0 秒。包括失联禁写及恢复、轮询单飞、旧 GET 不回退新写入、价格变化需重确认、已提交但响应丢失的单次对账、未提交冲突的草稿和操作标识保留及重新授权。
