# v0.3 独立 UI 验证记录

验证对象：仅「积分」「提醒」两核心模块，2026-11-15 冻结版。验证负责人：ux-verifier。

结果：真实浏览器合并检查 **35 项通过，0 当前失败，0 跳过，0 页面脚本异常**；客户端回归 **8 项通过**，其中原有 7 项完整保留并迁移，另加连接中断后的保护与恢复。

机器可读证据见 [v3-browser-results.json](v3-browser-results.json) 和 [v3-client-results.json](v3-client-results.json)。浏览器报告按组合并定向复测，保留每轮执行记录和后续各轮源码 SHA256；并不表示 35 项在同一轮执行。首轮的两项失败是测试选择器名称和回答文案断言适配错误，修正后对应组通过，历史失败保留在 runs 中。未发现仍未解决的已测产品缺陷。

## 实际执行方式

- 安装在本机的 Microsoft Edge / Chromium 无头浏览器，puppeteer-core；真实 DOM、鼠标坐标点击及 elementFromPoint 遮挡检查。没有使用 element.click() 绕过可达性。
- 五种视口：1440×1000、1024×768、768×1024、390×844、320×568。页面无横向溢出；仅两个固定导航 Tab；主要操作、面板关闭和提交按钮可达。允许内容区内部滚动。
- 浏览器业务套件使用独立临时数据文件与真实 HTTP 服务器；双页面同步使用真实 HTTP 轮询及刷新。
- 客户端回归仍使用真实 Edge 页面，但通过受控 XHR 完成顺序及轮询回调稳定复现竞态。其伪挑战/授权仅是客户端夹具，不作为后端安全证据。
- 每个浏览器组使用独立临时服务器和浏览器上下文。测试没有修改 4178 演示数据。相关后台任务全部结束并已收回结果。

执行入口为 [browser.cjs](../test/browser.cjs) 和 [client.test.cjs](../test/client.test.cjs)。首轮分别运行 `node --test test/client.test.cjs`、`node test/browser.cjs`，后续只对变更或新增的分组定向验证。

可独立复现全套浏览器检查（PowerShell）：

```powershell
$env:V3_OFFLINE='1'
$env:V3_GROUPS=$null
node test/browser.cjs
```

定向复测用 `V3_GROUPS`，例如 `layout,assistant-public`、`reminder-boundaries`、`offline,offline-hosted`。客户端新增断网场景及旧快照回归通过 `node --test --test-name-pattern='C4 |C8 ' test/client.test.cjs` 验证。

## 已验证行为

- 加分只在逐笔核验成功后写账；错误 PIN 不写账；取消后更改草稿会新建挑战；下一笔操作重新核验，无全局家长解锁。
- 真实核验请求在途时取消，并打开另一礼品草稿，再放行迟到成功响应：不写账、不提交原动作、不覆盖新草稿。
- 更改核验方式先用当前 PIN；算术题每次现场显示并答题，错误答案被拒绝，面板明确提示只能防误触。
- 子女申请与取消兑换均不扣分、不发起核验；家长确认后只增加已兑换积分、减少可用积分，累计获得积分保持不变。礼品名称/分值即可直接维护，无需图片。
- 常用项预览带入可核对的具体原因，用户可修改；点击模板不直接记账。新建第五个模板实际可选，维护需核验，使用时另需核验；后改模板不追溯修改旧账。
- 提醒完成公开操作、不加分；新建、编辑、删除逐笔核验；面板关闭或 Escape 后草稿保留。
- 前台到点提示真实出现；「10分钟后」隐藏后按受控时钟再次出现；「知道了」隐藏提示但不完成事项、不加分。已经到点的事项打开页面即呈现。
- 已知道但未完成的普通事项及重要事件跨日后仍可达；旧日期保留、编辑仍需核验，刷新后保留。提前准备区消费 remindDays：范围内事件显示，范围外事件只保留在重要事件列表，明天列表不混入今日提前准备区。
- 手机首屏礼品按钮真实点击后滚到礼品区域并能进入申请；日期标签不折成单字列；五视口截图均来自真实页面。
- 本地「指令演示」会生成可编辑草稿；输入本身不入账，敏感草稿仍逐笔核验。只读兑换差额根据已变化的真实账本计算；缺失原因追问；礼品/提醒句子可取消；不支持语音识别时有键盘入口。自然语言公开兑换申请仍先展示草稿，确认时不核验、不扣分。
- 音频资源有效且具有 RIFF/WAV 文件头；Edge 中减少动态效果设置生效。

## 原七项客户端回归映射

1. C1：首次成功同步前禁止写操作 → 保留为初次同步挂起/失败时公开和敏感写均被阻止，草稿不丢，恢复后重新确认核验。
2. C2：file 模式无需请求即可本地操作 → 实际 file 页面完成提醒并保存，无 XHR；最终打包文件另有完整离线检查。
3. C3：轮询单飞锁 → 成功和超时都会释放，未结束时不重入。
4. C4：延迟旧 GET 不回滚成功 POST → 内存、存储、版本号保持最新；有效旧响应也不会误报断线。
5. C5：礼品价格同步需要重确认 → 审批草稿显示新价、保留备注、先让用户复核再发起新的核验。
6. C6：超时/冲突/重试复用动作 ID 且只记一次 → 已提交但响应丢失后协调为单笔；下一次有意加分获得新 ID 和新核验。
7. C7：未提交冲突保留 ID 并更新版本 → 原因草稿和动作 ID 保留，必须取得新版本绑定的核验。
8. C8 为新增：曾连接后轮询超时、503 或坏 snapshot → 可见连接中断，禁止 challenge/action，草稿保留；有效数据恢复后可再核验提交。

## 明确未验证的边界

- 没有 iPad mini 4 / iPadOS 15.8.7 真机，也没有 Safari 执行结果。视口模拟不能替代 Safari/真机验收。
- 测了桌面 Tab/Escape 和小屏面板可达性，没有验证 iPad 软件键盘弹出/收起。
- 提醒用受控时钟推进，并由真实前台五秒定时器更新。没有等待十分钟自然流逝，也没有八小时设备长稳运行。
- 音频验证限于资源格式及加载；没有验证真实扬声器可听效果、实际麦克风录音、唤醒词或浏览器后台通知。
- 当前实测 AI 为本地指令演示，没有真实外部 LLM 请求。本机私有 PIN 流程仅演示，不能等同于服务器身份安全。
