# v0.8.1 常用加分选择器密度（Current）

日期：2026-11-16。用户指出 735×754 的加分面板空间利用率低：7 个项目被拆成两页，卡片约136px高，名称与分值间有明显空白。

## 问题与替换范围

[v0.5 满屏与直接交互](interaction-design.md) 的固定每页最多六项与等高拉伸，使新增项目触发不必要的翻页。本记录仅替换选择面板的卡片密度、页容量与单页分页展示。原记录继续拥有常用排序、搜索和页码输入稳定、返回草稿、至少48px触控等约束；账本、家长核验及AI未接通状态均不属于本次修改。

## 决定

- 使用88px高的紧凑卡片；布局视口高度不超过440px时为64px。名称最多两行，预设原因只预览一行，选择后在原加分表单查看全文；短屏省略原因摘要。
- 宽度至少700px时三列，窄屏两列。每页容量由可用视口高度、真实面板控件尺寸和卡片行高确定，多页时为分页栏预留空间。
- 单页隐藏前后页与页码栏，面板随内容收起，最高740px且不超可用视口。异常矮的键盘视口允许面板内容区滚动，控件保持可达。
- 搜索、管理、模式切换和分页保持48px触控目标；搜索与页码输入保留16px字号。不增加解释性界面文字。
- 列表重建时保留内部焦点，原项目离开当前页则退回搜索输入；隐藏分页不参与Tab循环。空结果横向并列显示状态与清除按钮，避免短屏按钮下缘被裁。

## 取舍与后果

拒绝只增大固定页数：矮屏与软键盘会遮住项目。拒绝按剩余空间继续拉伸卡片：搜索结果少时仍出现巨大空白。拒绝缩小整页或触控按钮：不符合手机和平板点按要求。保留有界分页，不改成无界长列表。

三列会减少单卡宽度，长名称和原因可能截断，原始内容完整保留在选择后的表单里。少量项目不再占满面板最大高度；320×568的7项仍合理分成4+3两页，不以压小按钮换取一屏塞入。
