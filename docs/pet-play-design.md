## 问题

主“加分”直接进入自定义表单，常用项另在主页与选择器，不能从同一个意图连续选择；自定义事实也不能在入账时固化。现有扁平小院角色虽变大，缺少冒险气质和有力动作；免费无限照料只改变短暂表情，没有资源、选择和可追踪目标。

## 决定与明确边界

### 一个加分入口

主加分进入统一选择器：“常用加分”与“自己定一项”都在面板内，搜索/分页/管理继续可达。主页常用快捷仍可直接选中。进入同一编辑表单后，可重新选常用，也可切换自定义，返回保留草稿和搜索页码。自定义表单提供“同时存为常用”，默认关闭；勾选后展示模板名称与保存效果。一次确认/一次家长核验原子完成加分和新模板，不先建模板再请求第二次授权。新记录关联该模板，立即参与最近30天排序。取消/失败不写任一部分，重试不能重复造模板。相同名称不静默覆盖已有模板。

合约：`points.add` 新增可选 `saveAsTemplate: true`，仅用于无 itemId 的自定义加分；模板ID由 action.id 确定，名字/分值/预设原因取本次确认字段。常用模板被选中后编辑本次金额/原因仍不自动改模板。

### 从空点击到短程探索

- 点角色的招呼/摸摸永远免费、不写账、不产生探索进度，没额度也能收到回应。
- 三种照料为投喂、清洁、训练。每天全家共享3次免费照料，按家庭服务器自然日计算，非连续登录奖励。刷新/改伙伴/换设备不重置。
- 免费额度用完后，使用已拥有的对应消耗品。必须明确显示“免费余量”或“消耗道具×1”；没有道具时打开补给入口，绝不暗中购买、扣分或自动切换到收费。
- 固定三种道具：`snack` 能量果（投喂）、`dew` 星露瓶（清洁）、`ball` 训练球（训练）；每件3积分，一次购买1–10件。购买需展示总价/余额变化并逐笔家长核验；购买后道具入背包，由孩子公开使用。余额不足不写任何部分。
- 每次真实成功照料增加1点“探索进度”；同一日首次完成三种不同照料再额外+1。探索进度是永久里程，不可花费、无衰减，也不换回积分。累计获得积分仍是唯一角色成长XP，消费和照料不改变它。
- 探索里程4/10/18/28/40/56依次解锁六处背景与徽章：微光森林、晶石洞穴、云海浮岛、流星营地、星环港湾、极光山巅。第一天3次免费照料即可完成三种照料并到4，立刻看到首个解锁。本次照料跨新门槛时同一事务自动前往新地点，使奖励在首页立即可见；没有新解锁的照料不改变已选场景。解锁后可自由切换背景，永不收回；无需抽奖、战败、倒计时催促、饥饿或断签惩罚。花完免费额度仍能摸摸、查看收藏和切换场景。
- 购买道具只增加照料机会和探索速度，不直接买成长XP，也不改变礼品的启用状态、类别或开放日期。礼品与道具共用可用积分，因此购买后可能暂时不够兑换已申请的礼品；申请不预留积分，审批会重新校验余额。账本分别展示支出来源。

### 数据、权限与兼容

旧v1状态补 `petPurchases:[]`、`petCare:[]`、`petScene:'home'`，不回填虚构照料；保留历史、家庭私有核验和幂等收据。购买与使用独立记账，库存/每日免费余量/探索/解锁由记录派生，避免可随意覆盖的余额或第二种货币。

- `pet.buy {itemId, quantity, expectedPoints}`：家长操作；只接受固定目录的服务端价格，expectedPoints是本次总价，重算校验；追加购买记录并扣可用积分。
- `pet.care {care:'feed'|'wash'|'train', source:'free'|'inventory'}`：公开操作；由当前时间及既有账本判断额度和库存，不接受客户端余量/日期/进度。仅成功使用消耗一次，重复action.id幂等；过期视图失败后重新显示可用资源，不默默扣另一种资源。
- `pet.scene {sceneId}`：公开；仅允许home和已解锁场景。
- `FamilyModel.petStatus(state,nowOrFamilyDay)`：统一公开投影。共享模式传服务器提供的 `familyDay:'YYYY-MM-DD'`，离线传本机 Date；返回 `familyDay`、`catalog:[{id,name,care,points}]`、`inventory:{snack,dew,ball}`、`freeLimit/freeUsed/freeRemaining`、`caredToday:[]`、`dailyBonusEarned`、永久里程 `exploration`、`scenes:[{id,name,threshold,unlocked}]`、`unlockedScenes:[id]`、`nextUnlock:{id,name,threshold,remaining}|null` 和 `sceneId`。场景ID按门槛为 `home/forest/cave/cloud/camp/harbor/aurora`。投影不修改数据，UI不维护另一套规则。
- HTTP 的 GET state、成功 action、409 冲突快照和 meta 附服务器 `familyDay`；日切即使 revision 未变化也应刷新界面。共享照料不以设备日期预演拒绝合法请求，最终消耗由服务端决定；断连不会本地恢复新额度。
- `FamilyModel.growthStages(kind)` 返回五阶段 `[{stage,at,name}]` 的独立副本，用于界面说明，避免手写旧名称。
- `totals.spent` 包含现实礼品和道具；`earned/available`原语义保留，成长仍只取earned。所有经济动作受版本并发和原幂等机制保护。服务端权限白名单只能增加care/scene，不能增加buy。

### 视觉与触控

采用原创“星岛探险队”风格：植物伙伴重塑为晶叶幼龙，水豚成为太空探险员。强调有层次的体积光影、明确轮廓、护具与探索装备，不依赖性别刻板印象或现有IP。成长五阶段有可辨的进阶装备/形态，保留plant/capybara兼容ID与已有昵称。

- 幼龙五阶段：晶卵初醒 → 晶叶幼龙 → 踏星小龙 → 星翼飞龙 → 星辉守护龙。
- 水豚五阶段：初见团团 → 好奇学员 → 星岛探员 → 银河领航员 → 星光守护者。

`FamilyPet.render({kind,stage,name,reaction,reducedMotion,framing,sceneId})` 沿用原入口，`framing:'hero'` 近景、默认 `scene`。`g.pet-character` 保留独立本体测量，不能借场景、平台和装备虚增尺寸。`FamilyPet.renderItem(itemId)` 提供同风格三种道具 SVG 和可访问标题；预览工具桥接正式渲染器，避免两套形象漂移。

每种照料有独立2–3秒动作、道具接触、轨迹/粒子与成功反馈；升级/解锁使用明显的一次性光环或星图展开，不能只有文字改动。首页保留大型角色、直接照料按钮和可见免费/库存状态；背包/补给/探索收藏通过明确入口打开，不把商店铺满首页。减弱动态时保留静态效果与文字；不使用持续闪烁、自动音频或重型WebGL。继续兼容iPadOS15.8.7，关键控件至少48px、输入16px，主页不能因新玩法出现滚动或压小本体。

## 替代方案

- 只把两个旧入口互相加链接仍需要猜路径，采用统一选择器和同表编辑。
- 自定义先保存模板再加分会出现半成功与重复核验，采用同一动作原子写入。
- 所有照料收费会让低余额孩子失去互动；全部免费无限进度又没有选择，采用免费日额度、可选存量道具与永远免费的招呼。
- 饥饿/断签/随机稀有抽奖不适合当前家庭，采用永久确定性里程与外观收藏。
- 让花积分直接增加角色XP会稀释现实行为奖励，分开累计成长与不可消费的探索里程。

## 验收条件

1. 模型/真实HTTP：旧数据无损；免费3次跨日恢复、旧日期/未来日期伪造无效；三种奖励只一次；刷新/换伙伴不刷额度；两设备争最后额度/库存不双花；购买未核验/不足/价格不符/非法数量均拒绝；正好够分、幂等重试、重启持久化有效；所有消费不减earned/XP。
2. 原子加分+模板：一次核验同时写一条账本与一个模板；取消/错误/重复/冲突不留下半成品，不覆盖同名旧模板；新模板可立即再次选择并正确排序。
3. 真浏览器完整路径：加分→常用/自定义→存常用→核验→首页；3次免费→首解锁→背包购买→核验扣分→用道具→刷新恢复；无道具/不足/取消均有清楚恢复路线，免费摸摸始终可用。
4. 八种既有视口、24长行为/40字名字/提醒待审压力仍无主页滚动；新增按钮实际可命中；角色本体最低240px(1024横屏)/170px(390×844)/100px(320×568)，不靠道具或场景冒充。美术必须实际看图和看动作差异，而非仅通过bbox。
5. 受影响AI、照片、待处理连续操作、授权竞态和离线file/HTTP契约回归。源码与导出精确一致；最终报告只对最终版本负责，保留v0.5交付与证据。
