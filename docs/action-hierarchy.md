# v0.10 全产品操作层级（Current）

2026-11-16。来源：用户连续指出新增与加分提交不醒目，要求自行逐页检查整套产品。授权覆盖统一视觉、操作标签和反馈，保持业务、权限、数据及iPadOS 15兼容边界。

本记录部分替换[App式操作](app-interactions.md)中将顶部提交弱化为普通文字的表现；原记录继续拥有导航位置、草稿、搜索、分页与逐笔家长核验边界。[自解释界面](self-explanatory-ui.md)的无解释性正文约束继续有效。

## 问题

主要提交、工具入口和普通文本视觉接近；只改＋遗漏了所有保存与确认表单。部分提交被统一缩写成“确认”，无法从按钮本身识别行为。错误放在滚动内容末尾，用户在顶部点击后可能看不到反馈。不同页面的按钮状态缺乏同一标准。

## 方案

- 保留已统一的导航：返回在左、工具在右、提交固定于右上；表单主按钮使用与首页加分相同的深绿实心、白字、48px以上触控区。＋沿用实心图标按钮。只读页不强造提交按钮。
- 按操作角色统一主操作、辅助操作、选择控件和危险操作；搜索/编辑/指令工具不能抢过提交。申请、兑换、购买、稍后提醒使用明确的短动作名；保存不增加重复底部按钮。
- 核验保持底部明确主操作，返回修改为次操作；取消提醒的最终确认采用危险色，仍经原有家长验证。
- 忙碌保留明确动作状态并阻止重复提交；不可用与处理中视觉区分。不可兑换/不可购买按原有业务判断保留禁用主按钮和短状态；不隐藏入口后让用户猜测。表单错误固定在导航下方，修改输入后清除过时反馈，保留输入、草稿和焦点。
- 清点首页、提醒、收件箱、积分记录、加分选择/表单/管理、兑换申请/审批/管理、孩子资料、家庭设置、家长设置/PIN/算术题/首次设置、指令、伙伴/背包/商店/成长/设置/购买。逐页检查主要动作、次操作、返回、空态和受限状态。

## 替代

- 继续逐个加颜色：无法形成统一规范和发现未指出页面的问题，不采用。
- 所有按钮都填深色：无法区分主要提交、工具和选择，不采用。
- 全部改为底部大按钮：增加滚动内容遮挡并撤回已有固定顶部操作，暂不采用；核验保留原底栏。
- 全面重写业务或组件框架：与此次可见问题无关，风险和耗时不合理，不采用。
