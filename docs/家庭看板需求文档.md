## 1. 文档概述

### 1.1 背景与目标

本工具面向家长自用，用于记录近期待办事项，并通过“只加不扣”的积分方式激励孩子的良好表现，再以积分兑换奖励形成正向循环。文档需明确三大模块的功能范围、字段定义、计算口径与边界规则，供后续实现与核对使用。

### 1.2 用户与使用场景

- 主要用户：家长（录入待办、设置加分项与兑换项、记录加分、发起兑换）。
- 使用场景：记录未来 1～3 天内（今天、明天、后天）需要完成的事项；孩子表现良好时手动加分并备注原因；日常用积分兑换文具类易耗品（橡皮、尺子等），周末带他去吃想吃的东西，月末带他去想去的地方玩（如长隆、其他城市）。

### 1.3 名词与口径约定

| 名词 | 定义与口径 |
| --- | --- |
| 累计总分 | 所有加分记录分值的总和。只增不减，永不清零，跨月、跨年持续累加；兑换动作不修改该数值。加分项清单与全部加分记录永久保留，不因兑换或月度结算而清空。 |
| 已兑换额度 | 所有兑换记录所消耗分值的总和，单独累计。 |
| 剩余可兑 | 计算公式：剩余可兑 = 累计总分 − 已兑换额度，即兑换界面展示的“可兑换积分”。兑换前须显示该数值，并校验其是否达到兑换项所需分值。 |
| 加分项 | 家长预先设置的良好行为类别及其对应分值，记录加分时可直接选用。 |
| 兑换项 | 可用于兑换的奖励及其所需分值，按使用场景分为三类：日常文具（易耗品）、周末美食、月度出游。 |

## 2. 模块一：待办提醒与重要事件

### 2.1 功能说明

本模块包含两类内容：近期待办与重要事件。近期待办用于录入今天、明天、后天（未来 1～3 天）要做的事，是主视图的默认展示内容；重要事件用于记录家人生日、大假期（如寒暑假、长假）、之后的计划等远期节点，独立成清单，不与近期待办混排。本模块为纯记录，不与积分挂钩，不产生加分或扣分。

### 2.2 字段定义

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 事项类型 | 枚举 | 是 | 近期待办 / 重要事件；默认近期待办，选择重要事件后放开日期限制。 |
| 事项标题 | 文本 | 是 | 事项的简要描述，如“周三围棋课”“妈妈生日”“国庆假期出行”。 |
| 日期 | 日期 | 是 | 近期待办：仅可选当天、+1 天、+2 天；重要事件：可选任意未来日期，不受 3 天窗口限制。 |
| 备注 | 文本 | 否 | 补充说明，如时间、地点、需携带物品、礼物清单。 |
| 提醒方式 | 枚举 | 否 | 重要事件可选提前 N 天提醒（如生日提前 7 天、假期提前 3 天）；近期待办默认当天显示。 |
| 完成状态 | 状态 | 是 | 待办 / 已完成，默认待办，可手动标记完成。 |
| 创建时间 | 时间 | 自动 | 记录事项录入的时间，系统自动生成。 |

### 2.3 重要事件（远期事项）

重要事件与近期待办共用同一录入入口，但按类型分开存放、分开展示，避免远期信息挤占近期视图。

| 项目 | 规则 |
| --- | --- |
| 可录入内容 | 家人生日、纪念日、大假期（寒假、暑假、国庆等）、之后的出行或活动计划、需要长期记住的节点。 |
| 日期范围 | 可选任意未来日期，不受未来 3 天窗口限制；跨月、跨年均可。 |
| 展示位置 | 独立“重要事件”清单，按日期从近到远排列；主视图（首页）仍以近期待办为默认内容，重要事件放在次要区域或折叠入口，避免干扰近期安排。 |
| 临近提示 | 当重要事件进入未来 3 天窗口时，自动同步显示在主视图的近期列表中，提示家长处理（如准备生日礼物、安排出行）。 |
| 历史保留 | 已过期的重要事件归档保留，形成家庭事件记录，不删除数据。 |

### 2.4 展示与交互规则

- 按日期从近到远排列，同一天内的事项集中分组展示。
- 主视图的近期列表仅展示当前日期起 3 天内的事项；独立的重要事件清单按第 2.3 节规则展示远期事项，不受该窗口限制。已过期或已完成的历史事项归档保留，不删除数据，可在归档列表查看。
- 支持新增、编辑、删除事项，以及标记完成 / 取消完成。

## 3. 模块二：表现加分

### 3.1 功能说明

孩子表现良好时，家长手动记录加分。本模块只有加分，没有扣分；不设置惩罚性减分项，不与待办完成情况自动联动。每一笔加分都必须记录加分原因（备注），便于回溯行为表现。

### 3.2 加分项设置

家长可自行维护加分项清单，每项包含行为名称与对应分值，记录加分时直接选用，也可临时填写自定义行为。

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 加分项名称 | 文本 | 是 | 良好行为类别，如“主动完成作业”“安静听课”“整理房间”。 |
| 分值 | 数值 | 是 | 该项对应的加分数量，为正整数；不允许设置负分值。 |
| 启用状态 | 状态 | 是 | 启用 / 停用；停用后不出现在加分选择列表中，历史记录保留。 |

### 3.3 加分记录字段

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 加分项 | 选择 / 文本 | 是 | 从已启用加分项中选择，或临时填写自定义行为。 |
| 加分分值 | 数值 | 是 | 本次加分数量，默认带入所选加分项分值，可手动调整，必须为正数。 |
| 加分原因备注 | 文本 | 是 | 记录本次加分的具体原因，如“今天作业独立完成，没有催促”。 |
| 加分日期 | 日期时间 | 自动 | 默认记录当天当前时间，可回溯修改为当日其他时间。 |

## 4. 模块三：积分兑换

### 4.1 功能说明

家长预先设置可兑换的奖励项目及其所需分值，按三类分层使用：日常文具类易耗品随时可兑，周末外出用餐在周末兑，月度出游在月末兑。所有兑换都只消耗“可兑换积分”，只生成兑换记录、累计已兑换额度，不从累计总分中扣减分值，也不修改或删除任何加分记录；累计总分始终保留全部历史加分。

### 4.2 兑换项设置

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 兑换项名称 | 文本 | 是 | 奖励名称，如“橡皮一块”“尺子一把”“周末吃火锅”“长隆一日游”。 |
| 所需分值 | 数值 | 是 | 兑换该项需要达到的可兑换积分（剩余可兑），为正整数。 |
| 兑换类型 | 枚举 | 是 | 日常文具：易耗品，如橡皮、尺子、铅笔、本子，随时可兑。<br>周末美食：带他去吃想吃的东西，周末可兑。<br>月度出游：带他去想去的地方玩（如长隆、其他城市），月末可兑，占用可兑换积分。 |
| 启用状态 | 状态 | 是 | 启用 / 停用；停用后不可被选择兑换，历史兑换记录保留。 |

三类兑换层级与典型内容：

| 层级 | 典型内容 | 可兑时间 | 规则要点 |
| --- | --- | --- | --- |
| 日常文具 | 橡皮、尺子、铅笔、本子等易耗品，分值门槛低 | 随时（含周一至周五） | 高频小额，可随时兑，用来及时兑现短期好表现。 |
| 周末美食 | 带他去吃想吃的东西，如火锅、汉堡、餐厅 | 周六、周日 | 不设次数与分值上限，积分够即可连续兑。 |
| 月度出游 | 去想去的地方玩，如长隆、周边或其他城市 | 每月月末 | 分值最高，占用可兑换积分，可兑数量由当月积分决定。 |

### 4.3 积分计算口径（关键规则）

- 累计总分：所有加分记录分值之和，只增不减，跨月累计，不清零。
- 已兑换额度：所有兑换记录分值之和，单独累计，不回写、不冲减累计总分。
- 可兑换积分（剩余可兑）：剩余可兑 = 累计总分 − 已兑换额度。兑换界面必须显示该数值，作为唯一兑换判断依据。
- 兑换校验：发起兑换时，界面先显示当前可兑换积分；该数值达到兑换项所需分值方可兑换。兑换成功后新增一条兑换记录，已兑换额度增加对应分值，累计总分、加分项与加分记录均不变、不减少。
- 记录可追溯：每笔兑换记录关联对应兑换项、所需分值与兑换时间，便于核对奖励发放情况。

### 4.4 兑换时间规则

| 时段 | 规则 |
| --- | --- |
| 周一至周五 | 开放日常文具兑换（橡皮、尺子等易耗品）；周末美食与月度出游不可兑。页面始终显示可兑换积分，文具兑换后实时刷新该数值；除文具外其他兑换入口不可用。 |
| 周末（周六、周日） | 开放周末美食兑换（带他去吃想吃的东西），同时可兑日常文具。不设兑换次数上限，也不设分值上限：只要可兑换积分达到对应分值即可兑换，可连续兑换，直到积分不足以再兑换为止。每次兑换后实时刷新可兑换积分。 |
| 每月月末 | 开放月度出游兑换（长隆、其他城市等），占用可兑换积分。每月可兑数量不设固定上限，由当月可兑换积分决定：积分足够即可兑，兑到不足为止。兑换后同样实时刷新可兑换积分。 |

### 4.5 兑换记录字段

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 兑换项 | 选择 | 是 | 从已启用兑换项中选择，区分日常文具、周末美食与月度出游三类。 |
| 消耗分值 | 数值 | 是 | 兑换该项计入已兑换额度的分值，默认带入兑换项所需分值。 |
| 兑换备注 | 文本 | 否 | 记录奖励发放情况或补充说明。 |
| 兑换时间 | 日期时间 | 自动 | 记录兑换发生的时间，系统自动生成。 |

## 5. 页面信息架构（建议）

- 首页 / 总览：顶部展示累计总分、已兑换额度、可兑换积分；下方以未来 3 天待办为主，重要事件折叠展示（临近 3 天时自动置顶），并展示最近加分与兑换记录。
- 待办页：统一录入入口（近期待办 / 重要事件二选一）；近期待办按日期分组为主列表，重要事件为独立清单。
- 加分页：加分项选择、分值与备注录入，历史加分记录列表。
- 兑换页：顶部固定显示可兑换积分；兑换项列表标注所需分值并实时标记是否可兑；兑换入口、历史兑换记录。
- 设置页：加分项维护、兑换项维护。

## 7. 前序会话补充：设备、部署与语音输入

本章记录本次业务需求之前的讨论，区分已知事实、使用诉求与尚未确定的实现方案。不得据此把建议直接当成已实现或已确认的技术方案。

### 7.1 已知事实与使用诉求

- 展示设备：用户有一台较旧的 iPad mini，具体代际与 iOS / iPadOS 版本尚未提供。
- 展示诉求：希望设备保持亮屏，展示积分、计划等内容，供家人随时查看，并希望具备提醒能力。
- 部署条件：用户已有服务器，可考虑发布到自己的服务器；域名、HTTPS、服务器配置与网络可达性尚未核实。
- 计分对象：以第 6 章确认的单孩子、单账户为准；家人查看不代表需要为多人分别计分。
- 语音诉求：用户已询问是否可以语音输入。将其记录为补充需求候选，具体功能范围、交互方式与首版优先级待确认。

### 7.2 已讨论的实现方向（建议，待确认）

- 提供家庭看板网页，由用户服务器保存待办、事件、加分项、加分记录、兑换项及兑换记录。
- iPad 作为常驻看板；手机可使用适配后的管理页面修改内容，数据同步到 iPad。
- 优先保证旧 Safari 的基础浏览与交互兼容性，采用大字、清晰按钮和较少动画；支持时再提供添加到主屏幕的独立网页应用体验。
- 设备常亮结合系统自动锁定设置与可用的引导式访问功能处理；实际效果须在该 iPad 上验证。
- 日常使用由长期在线的服务器提供服务，不要求开发电脑或 DSH 持续运行。
- 网页 / PWA 是已建议的方向；本阶段未确认开发微信小程序或原生 iPad App，也尚未实施任何部署。

### 7.3 语音输入候选范围（待确认）

- 基础方式：输入框配合系统键盘听写；是否可用取决于该设备的系统功能与设置。
- 增强方式：页面提供“说话”按钮，用户主动启动录音，服务端识别为文字；再根据需要解析成待办草稿、加分草稿等。
- 建议交互：点击说话 → 显示识别文字及解析字段 → 家长修改或确认 → 按对应模块规则保存。
- 语音不得绕过业务校验。例如，加分仍需正分值与原因；近期事项仍限今天、明天、后天；远期计划须按重要事件处理。
- 示例语句：“明天提醒我给孩子带水杯”“给孩子加 5 分，原因是主动整理房间”。以上仅为交互示例，不代表已录入真实事项或积分。
- 服务端语音识别可采用外部服务或自部署模型，选型、费用、录音处理与保存策略尚未确定。
- 若旧 iPad 的录音兼容性不足，可考虑系统听写或手机管理页语音输入，再同步显示到 iPad。
- 全天候监听、唤醒词和锁屏后持续收音未列为已确认需求，不能默认承诺旧 iPad 网页具备这些能力。

### 7.4 提醒能力边界（待确认）

- 第 2 章已明确近期事项按日期显示、重要事件可提前 N 天提醒；提醒的具体渠道、时刻和频率尚未定义。
- 页面在前台时可评估视觉提示、提示音等方式；声音启用与持续运行效果须在目标设备上验证。
- 锁屏、退出页面后通知到 iPad 或家人手机属于另一类能力，不能等同于前台提醒，也不能仅凭已有服务器就认定可用。
- 添加到主屏幕的网页推送需要支持的系统、授权与服务端配合；旧 iPad 的能力需根据实际系统版本核实。

## 9. 验收检查清单（待验证）

本章用于后续实现核对，不代表已执行测试。下述数值均为验收示例数据；受第 8 章未定规则影响的场景，待规则确认后补充预期结果。

### 9.1 待办与重要事件

- [ ] 默认新建类型为近期待办；仅允许选择今天、明天、后天。跨月、跨年时仍按这三个自然日期处理。
- [ ] 切换为重要事件后，可录入三天窗口以外的未来日期，并进入独立清单。
- [ ] 主视图默认以近期事项为主，远期事件不挤占近期列表；重要事件进入三天窗口后自动出现在近期视图。
- [ ] 事项可新增、编辑、标记完成和取消完成；主动删除的最终行为按 Q07 确认结果验收。
- [ ] 已过期、已完成的事项可在归档中查看；过期重要事件保留历史。
- [ ] 完成、取消完成、过期或删除事项都不会自动增加或扣减积分。

### 9.2 表现加分

- [ ] 可维护加分项；其配置分值必须为正整数。停用项不再出现在新增加分选择列表，历史记录仍可查。
- [ ] 记录加分可选用已启用项目或填写自定义行为；分值默认带入，允许按最终数值规则调整，零分和负分不能保存。
- [ ] 未填写加分原因不能保存；没有惩罚性扣分入口。
- [ ] 加分时间默认当前时间，可回溯为当日其他时间，不默认开放跨日补记。
- [ ] 某加分项从 5 分改为 8 分后，历史已发生的 5 分记录保持 5 分；新记录按新设置默认带入。

### 9.3 积分计算与兑换

- [ ] 示例：累计总分 100，已兑换额度 30，则剩余可兑为 70；各页面口径一致。
- [ ] 在符合时间规则且奖励启用的前提下，兑换需 20 分的奖励后，累计总分仍为 100，已兑换额度变为 50，剩余可兑变为 50；新增对应兑换记录，全部加分记录保持不变。
- [ ] 在相同前提下，剩余可兑恰好等于所需分值时允许兑换，兑换后为 0；不足时拒绝兑换且不新增成功兑换记录。
- [ ] 月份、年份切换不清零累计总分，不删除加分项、加分记录或兑换历史；结余按累计口径继续计算。
- [ ] 非月末的普通工作日开放日常文具，关闭周末美食和月度出游；普通周末开放日常文具和周末美食。月末范围及重叠日行为待 Q01、Q02 确认后补齐。
- [ ] 在允许的日期中，三类兑换均不设置固定次数或额外分值上限，仅在可兑换积分足够时成功；每次兑换后及时刷新剩余可兑。
- [ ] 停用奖励不可用于新兑换，已有兑换记录仍可追溯；每笔记录包含对应兑换项、消耗分值及兑换时间。
- [ ] 全系统仅维护一个孩子的一套积分，不引入多孩子或家庭成员独立计分。

### 9.4 设备与补充能力

- [ ] 若确认采用网页看板及联网同步方案，在设备型号和系统版本明确后，于实际旧 iPad mini 上验证页面打开、字号、触摸操作、长时间展示和重新联网后的同步。
- [ ] 若确认采用用户服务器部署，验证设备与管理端访问同一份数据，且日常使用不依赖开发电脑或 DSH 常驻。
- [ ] 若语音列入实施范围，验证录音 / 听写、识别结果编辑、确认保存和不可用时的文字输入回退；所有操作仍遵守三大模块规则。
- [ ] 按最终确认的提醒范围分别验证前台视觉 / 声音提示与后台 / 锁屏通知；未纳入实施范围的能力不作为必验项，也不得承诺可用。
