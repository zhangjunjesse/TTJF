# 指定本机初始用户（Current）

日期：2026-11-17。用户在配置自己邮箱 SMTP 后，明确指定同一邮箱和登录密码作为默认管理员或默认用户。本记录只拥有这次本机账号初始化；[SaaS基础决定](saas-design.md)继续拥有注册、认证和家庭隔离，[完整内测决定](saas-completion.md)继续拥有家庭生命周期。

## 问题

指定账号已经注册但尚未验证邮箱，没有家庭；用户希望直接使用自己指定的初始账号进入应用。产品只有家庭内的 owner / parent，没有平台超级管理员。

## 决定

- 按用户本次授权，一次性准备指定本机数据库中的账号，保留现有用户ID，设置指定密码，以现有 scrypt 算法存储。
- 用户已提供同一邮箱的可用 SMTP 授权，且明确要求初始化该账号。本次由本机操作者按该授权确认邮箱；普通注册仍须通过邮件验证。
- 同一事务更新账号、撤销其既有会话、消费未使用邮件令牌、清除该账号的家长核验凭据。所有更新都限定该用户ID。
- 保留空家庭列表；用户登录后填写家庭名和孩子称呼，创建家庭时按原有接口获得该家庭 owner 权限。
- 凭据不写入源码、文档、测试夹具或环境默认值。本次操作通过临时进程执行，不增加初始化脚本、公开接口、默认密码或平台超管。

## 变化与替代方案

原基础决定 v0.13 交付“不替用户注册账号/设置密码”的操作范围，由本次明确授权针对指定账号放宽。禁止自动接管旧家庭、禁止跨家庭访问、普通注册邮件验证和无源码默认凭据均保留。继续要求用户手动完成原验证邮件也可行，但不能直接满足已授权的初始账号准备；内置通用默认密码或增加平台超管超出了本次需要。

## 后果

账号已经可正常登录，服务重启不重置密码或重复创建用户。新部署和数据库重建也不会自动复建该用户。家庭名称与孩子称呼由用户首次登录填写，不从旧存档猜测或导入。以后改密仍使用正常账号操作。已消费的旧验证邮件不能再次使用。
