# v0.5 满屏与直接交互（Current）

日期：2026-11-15。依据用户对已交付 v0.4 的纠正：默认未占满屏幕；常用行为需要下拉查找，应自动把常用的放前面并用入口展开全部；宠物本体过小；必须以交互为判断标准。

本文局部替换 [成长设计](growth-design.md) 中允许积分首页纵向滚动、按固定高度陈列小院和展示全部启用行为的决定。成长规则、AI/照片、逐笔核验、账本与提醒规则继续由原记录拥有。本次由用户直接授权实施，不增加设备权限、外部服务或费用。

后续边界：用户已授权且已完成验收的 [v0.6 统一加分与伙伴探险](pet-play-design.md)，替换本记录中的割裂加分入口、旧造型、三种无限免费照料与照料不写请求的断言；首页满屏、排序、选择器输入稳定、触控目标、真实本体尺寸和连续待处理仍保留。下面的 v0.5 完成记录是历史证据，不代替 v0.6 验收。

## 当前展示边界

v0.12[伙伴小农场](farm-design-proposal.md)拥有3D近景和连续世界展开视图；无滚动、常用行为、48px触控和近景本体尺寸要求保留。真实截图的轮廓、比例、材质和场景构图是独立验收项，测试数量和本体尺寸不能替代它。3D本体用实际解剖几何顶点投影度量，排除地面、尾翼与特效，不再要求SVG/DOM组。原SVG度量是历史实现。

[v0.7自解释界面](self-explanatory-ui.md) 拥有跨界面文案精简策略，移除说明段落、注释、示例与教学，不替换本文的尺寸、占屏、输入稳定、焦点与连续处理约束。[v0.9 App式操作](app-interactions.md) 进一步统一面板导航、新增/编辑/保存入口与按需搜索；返回草稿和输入稳定继续保留。

## 被纠正的前提

v0.4 的外壳占视口，但主内容 max-width 1280、固定高度卡片使大屏留空；积分主区允许滚动，行为数量增加会把核心操作推到下方。角色 SVG 占满场景不等于宠物本体明显，小院宽景把角色压小。上一版验收允许手机纵向滚动且主要测四个种子行为，不能证明本次要求。

## 实施决定与边界

- 积分主区跟随当前可用视口宽高，取消内容最大宽度与页面纵向滚动。不是依赖浏览器 Fullscreen API；Safari 浏览器工具栏由系统控制。
- 横屏使用操作区与大伙伴双区；竖屏重排为紧凑的积分操作与大伙伴。随高度分配空间，避免仅加大卡片外框。首页所有关键动作直接可见并可点。
- 首页只展示最常用的少量启用行为：宽屏最多四个，窄屏最多两个。按最近 30×24 小时实际成功加分次数降序（闭区间 `now-30d ≤ at ≤ now`），同频按最近成功时间，再按原配置顺序。以 itemId 归属；不按分值、打开次数或取消草稿排序。无历史保持原顺序。只派生，不新增计数状态、不改变账本。
- “全部行为”是明确按钮，打开可搜索、可分页的选择面板，不使用下拉框或无界长列表。[v0.8.1 选择器密度](compact-picker.md) 局部替换原固定最多六项/短屏四项与拉伸卡片：按实际宽高计算容量，单页隐藏分页。多页时前后页与数字页码仍能直接到任何行为，空结果有清除入口；管理仍可达。搜索、中文组合输入和页码提交保留对应 DOM 与焦点，不能因重绘丢字或吞掉第一次点击。
- 从常用或全部选中后进入同一加分表单。取消/错误核验不加分；实际保存成功回到积分首页，看见积分变化和伙伴回应。取消选择保留返回路径和原草稿。
- 首页反馈由伙伴标题的已有行短暂承接，显示本次加分或互动回应，再恢复伙伴名；保留成长值和完整余额，不新增挤压角色的常驻行。不能仅因浮层不拦点击就认为它没有遮挡信息；实际截图必须能看到更新后的余额。
- 默认采用以角色为主体的近景渲染；新角色和照料规则由 [v0.6 伙伴探险](pet-play-design.md) 定义，本记录继续约束实际体积。角色轮廓需有可独立测量的 DOM 组，测角色本体而非 SVG 外框。表情、互动道具与反馈不能被放大裁切。
- 提醒到点和待审批时也不得把首页撑出屏幕，合并为顶部待处理入口。打开后支持连续“知道了”、稍后提醒、完成或取消申请，成功处理保留面板、更新计数并保持焦点在面板内；全部处理后显示空态，由用户关闭。审批仍逐次核验，取消核验保留当前路径。提醒页、编辑表单、历史明细可合理滚动。
- 保留至少 48px 主要点击目标、16px 输入字体、键盘与减少动态效果支持；不得用整页缩放压小字号和按钮来凑屏。

## 验收标准与证据

1. 1920×1080、1440×1000、1024×768、768×1024、960×540、390×844、390×667、320×568，积分主页 scrollHeight 不超 clientHeight（允许 2px 舍入）；关键元素不能靠 overflow:hidden 隐藏，逐个检查边界与实际命中。
2. 正常/提醒显示/待审批/两者同时、0/1/4/24 个行为、40 字昵称与长行为名称，都不撑破默认主页。
3. 首页行为数量受限且排序正确，选择面板搜到和翻页到第 24 项，返回/清除/选择后保存链真实可用；正确计数仅来自成功的加分，停用立即排除，同分和无记录稳定。
4. 1024×768 的第三阶段角色本体至少 240px 高；390×844 至少 170px；320×568 至少 100px。两种五阶段和反应的实际 SVG 几何可见；角色大小目标不得靠把装饰计入实现。若空间冲突，优先简化重复文案和说明入口，不隐藏核心操作。
5. 触碰角色保留即时免费回应；三种照料的计次、库存和变更请求由 [v0.6 伙伴探险](pet-play-design.md) 验收。核验后加分回首页，余额、排序和成长一致。v0.5 的纯免费无写入互动不再约束新版照料。
6. 独立 QA 复核真实截图和完整点击路径。旧版 AI、资料、兑换、客户端竞态及离线契约受影响路径回归；保留历史证据，不将旧版检查数量当作本轮通过。
7. 最终离线 HTML 与当前源码一致，file/HTTP 都保持本机模式；更新预览、设计状态与源码包。真实 iPad/Safari、真实外部模型和长期常亮边界继续明确。

## 完成记录

2026-11-15 独立最终整套验收通过：浏览器 68/68、同源客户端 8/8，加上本轮未受后续 UI 修改影响的核心 111/111，共 187 个顶层检查。128 个内容压力组合、80 组角色几何和 7 组反应是其中的展开覆盖，不重复累计。八种视口主页均填满主区域，无页面/主区域滚动，关键动作至少 48px 且实际可命中。

第三阶段植物/水豚本体实测：1024×768 为 383.76/393.43px；390×844 为 248.14/254.39px；320×568 为 112.34/115.17px，均达到本记录门槛。测量不把花盆、垫子、头饰和场景算入本体；手机因宽度约束，本体约占外层场景高度的 60–62%，不宣称每屏均为 82%。

检查进一步修复了页码和组合输入重绘失焦、加分浮层遮住余额、处理一条事项就关闭面板，以及大屏反馈字形底部裁切。最终加分反馈使用伙伴标题既有行，实际余额、成长值与伙伴同时可见；连续处理、审批返回、空态和 Tab 焦点均已验证。

可复核的逐项结果、最终源码/HTML 散列、截图和历史修复证据见 [v0.5 独立验收记录](../artifacts/v5-verification.md)。目标设备的真实 Safari、系统软键盘、麦克风与长期常亮仍需真机验证；本记录的 Current 表示上述实现及浏览器验收已成立，不表示通过硬件验收。
