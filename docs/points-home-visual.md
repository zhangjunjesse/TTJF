# 积分首页截图复查

手机使用单栏积分首页，平板使用双栏。两个尺寸共用头像入口、账本语义和分区导航。下面的截图入口可复用于后续首页优化。

## 固定场景

`test/points-home-visual.cjs` 使用项目已有的真实 SaaS 浏览器 fixture：每次新建临时 SQLite、合成账号和家庭，通过真实 API 与家长授权生成数据，完成后清理临时资源。不会连接生产服务或读取真实家庭数据。

默认家庭“小宝”有 4 个常用行为、9 笔记录、13 分余额。传入 `--family sparse` 可复现“小米”的日常使用情况，包含 1 个常用行为、14 分余额、今天 1 笔加分和跨日的最近记录。两类家庭各自与同尺寸、同数据的基线比较。

主要视口为 **390×665 CSS 内容区**，不含 Safari 地址栏和底栏。`small-phone` 为 320×568，`ipad` 为 768×1024，覆盖窄屏和双栏。实体 iPad/Safari 需单独验收。

## 一轮复查

每轮先写下家长此刻要回答的问题。积分首页的顺序是「给谁记」「记什么、加几分」「刚才记对了吗」。审视首屏上的每个标题、图标和按钮时，先说清拿掉它会失去哪条信息。当前选中的「积分」已经标明位置，日期在具体记录和七日小结里有上下文，手机首屏可以直接显示积分。头像上的相机表示编辑照片；涉及账本的「加分」「兑换礼品」保留动词，让人能够预测点击结果。

1. 修改前运行一组，保存基线：

   ```powershell
   node test/points-home-visual.cjs --label before --viewport phone
   node test/points-home-visual.cjs --label sparse-before --family sparse --height 844 --acceptance baseline
   ```

2. 打开终端所示目录的 `home-initial.png` 和 `home-bottom.png`，查看首屏与滚动到底后的实际呈现。结合 `results.json` 列出具体问题，例如“钱包占 252px”“第 3 条记录只露出部分”“按钮被遮挡”。先明确本轮要改善什么，再改相应的手机样式。

3. 改完后用同一视口复跑，并传入基线的 `results.json`：

   ```powershell
   node test/points-home-visual.cjs --label after --viewport phone --compare data/ui-home-visual/<基线目录>/results.json
   ```

4. 打开自动生成的 `compare.png` 看前后首屏，再看底部图。对比图在无业务数据的独立离线页面中，仅将两张本地合成截图以相同原始尺寸并排，标注“改版前”“改版后”，原图保留。核对信息顺序、留白、数字层级、小字可读性、记录和图表有没有裁切。以同尺寸实图为依据，不把“主卡更矮”直接当成“首屏能完整看到更多记录”。需要调整时，换新标签重复本轮，不覆盖旧证据。

5. 交付前补跑窄屏和平板，再按下面的清单对照：

   ```powershell
   node test/points-home-visual.cjs --label final --viewport small-phone
   node test/points-home-visual.cjs --label final --viewport ipad
   ```

也可使用 `npm.cmd run test:home:visual -- --label after --viewport phone`。PowerShell 下优先用上述 `node` 或 `npm.cmd`，避免 `npm` 的 PowerShell 启动脚本解析掉参数。`--width`、`--height` 可覆盖预设尺寸；每次只运行一个短组。

## 交付前对照

- 用有四个常用行为的家庭，检查手机竖屏可直接点到第四项。运行独立的 `DEVICE_HOME_CASE=phone-award` 浏览器组，从「自己刷牙 +1」进入核对和家长 PIN，检查回执中的名称、时间、分数以及首页的最新记录，核实数据库只新增一笔。
- 用只有一个常用行为的家庭，查看这项行为在整行中是否容易发现，罗列次数是否重复。390×844 检查长屏的段落间距，320×568 检查主操作和三个滚动可达的完整记录。记录行数用于描述截图，避免为了多露出一行缩小正文或字号。
- 截图复查要包括操作中途。并排查看同尺寸的 `phone-brush-preview.png` 和上一版核对图，确认孩子、行为、分值和时间容易辨认，原账本仍作为背景。用 `DEVICE_HOME_CASE=phone-award-draft` 检查家长修改过的分值、原因及记录时间能继续编辑，取消后账本没有新增记录。
- 三个展示值与今日笔数正确；截图与滚动没有写业务数据。
- 首屏的头像、积分/伙伴切换、设置、加分、兑换、底栏及助手入口可点击，命中区至少 48×48 CSS px。
- 对照截图检查头像上的相机在实际尺寸下是否完整。点相机应进入孩子资料，那里才出现选照片的文字。逐项确认省掉文字的入口仍有明确的读屏名称。
- 无横向溢出，无浏览器脚本错误；底部内容能通过正常滚动查看，七日图横轴文字均保持单行。
- 同尺寸比较卡片高度、最近记录起点、完整/部分可见行数和滚动余量；最终结论与截图一致。
- 320px 宽的积分和按钮完整，平板的钱包与七日小结并排。两个尺寸的读屏用户均可按一级标题定位积分页。
- 本轮输出为 `passed`，`sourceStable` 为 `true`。运行中若源码发生变化，重新跑一组；失败、未跑或原生设备未验收的项目如实说明。

## 证据文件

每轮输出到忽略目录 `data/ui-home-visual/<标签>-<宽>x<高>-<时间>-<进程号>/`，保留历史：

- `home-initial.png`、`home-bottom.png`：实际浏览器截图。
- `compare.png`：传入 `--compare` 后生成的同尺寸首屏对比图，仅使用本地合成截图。
- `results.json`：固定数据、区块矩形、字号、控件命中和可见性、记录露出比例、滚动余量、源码 SHA256，以及可选的前后比较。
- `run.log`：逐步落盘进度，便于中断后定位。
- `fixture/`：已有 SaaS fixture 的详细合成测试报告。

不保存源码副本；用 Git、文件哈希和独立截图目录追溯对应版本。每次改版后应审阅截图，自动尺寸检查不能替代视觉判断。
