# 积分与提醒核心重设计（v0.3 设计与验收记录）

状态：v0.3 已实现并完成下述历史验收。2026-11-15 用户授权的 [v0.4 高频积分与陪伴成长](growth-design.md) 已实现并完成新版验收，局部替换本文的首页优先级、成长表现及仅全局 AI 入口的取舍。本文继续拥有账本口径、逐笔核验、兑换和提醒的基础约束，以及语音/真机能力边界。目标设备为 **iPad mini 4 / iPadOS 15.8.7** 和手机；现代浏览器尺寸模拟不等于 Safari 真机通过。

## 当前展示边界

2026-11-16更新：[v0.13多家庭SaaS](saas-design.md)替换单户匿名服务的身份与存储边界。每个家庭仍是一个孩子、一套账本和一个农场；owner/parent是成人账号成员，不新增计分对象。下文“公开”在SaaS中均指已登录、邮箱已验证且属于该家庭的人可操作。每笔核验另绑定家庭、账号和会话，数据库事务替代进程内文件结算；旧JSON/离线演示保留为独立路径。原积分、兑换、提醒和成长规则不变。

v0.12[伙伴小农场](farm-design-proposal.md)添加与家庭积分隔离的作物库存和建设。六个农场动作公开，但不能加分、退款或改变家庭账本；成长继续从累计获得派生。开启后的旧补给停止出售，历史道具支出和已购库存保留。逐笔家长核验、礼品与提醒约束不变。

用户在v0.6交付后要求取消所有界面的说明性文字。[v0.7自解释界面](self-explanatory-ui.md) 拥有最新展示策略：本记录的能力、权限和数据边界继续有效，界面以明确控件、对象/金额和简短状态表达，长篇能力说明与操作教学留在项目文档。

## 问题与依据

用户明确指出积分和提醒是两个核心，要求快速准确加分、孩子清楚兑换、家长专属权限、方便添加礼品和管理提醒，并去掉非核心功能。此前将产品定位成孩子专注工具，不符合原始需求中的“主要用户：家长”。

[v0.2](app-design.md) 有可运行界面与技术回归，但名义上的家长入口不能隔离管理权限；布局通过不能证明产品流程成立。本轮替换其产品组织方向，[原业务需求](家庭看板需求文档.md) 继续拥有账本口径、三类礼品及近期/远期事项规则。

## 定位与实现范围

家长主导、孩子参与的家庭积分与提醒工具，一户一个孩子、一套账本。

- 一级模块仅“积分 / 提醒”；“说一句”是共用输入入口，不是独立聊天业务。
- v0.3 的积分/礼品双栏现由 [v0.4 高频积分与陪伴成长](growth-design.md) 局部替换：首页优先加分、常用行为与伙伴，礼品收进次要面板，待审批仍可直达。
- 提醒页提供今天/明天/后天、重要事件以及就近的新建和编辑入口。到点提示跨两个模块显示。
- v0.3 撤回独立成长页、心愿养成、专注模式和大幅装饰。v0.4 将伙伴成长嵌入积分页，仍不恢复独立成长一级模块或专注模式。手动操作始终保留，AI 不构成使用门槛。
- 完成提醒不加分、不扣分；积分变化只能来自家长明确授权的记账操作。

## 按操作核验

用户于 2026-11-15 修正：日常家长和孩子都能做的操作默认展示、不限制；仅家长专属操作核验，可以选择固定密码或算术题。因此不按设备划分身份，也没有全局家长解锁模式。

公开操作为：查看余额/明细/礼品/提醒、申请或取消未确认兑换、知道了、延后 10 分钟、完成/恢复完成。完成状态不影响积分，故本轮将它与管理提醒分开。v0.4 新增的伙伴互动、换伙伴与伙伴改名同样公开；用户后续授权的 [v0.6 伙伴探险](pet-play-design.md) 已将照料改为消耗免费额度或已购库存，仍不直接扣积分，购买道具则必须家长逐笔核验。

家长操作为：加分、最终兑换、加分项/礼品维护、提醒新建/编辑/取消，以及家庭设置和验证设置。v0.4 的孩子名称、头像保存与移除也必须逐笔核验。模型/API 的恢复删除同样受保护，当前页面没有另加归档模块。

每次受限操作先显示完整待保存内容，再核验；没有残留解锁时段。挑战绑定**完整动作内容与数据版本**，120 秒有效，成功换取 60 秒单次授权。换金额、换对象、新动作 ID、过期或版本变化都不能复用。取消时客户端丢弃迟到授权；服务器保留的未提交令牌仍只对应原操作并短期过期，不宣称取消会跨网络即时撤销服务器内存令牌。

首次配置与修改入口由 [v0.8 家长验证首次设置](parent-onboarding.md) 拥有，替换本记录原“控制台随机初始PIN”的决定：新家庭在页面设置，已有凭据保留。配置后PIN采用私有加盐scrypt，不放进页面、业务导出或公开状态；新PIN界面使用6位输入。单个挑战三次失败即销毁，家庭五次失败后暂限五分钟，另有请求频率限制。更改已配置的验证方式必须通过当前方式。

算术题由服务端生成并校验，只是轻量防误触。8 岁孩子可能答出或借助计算器，不能声称与 PIN 等效，更不能把核验视为法律意义的成年身份验证。

离线单文件先让家长自设 PIN，私有盐和散列独立存储，不随业务记录导出。这是本机交互演示；浏览器本地存储不等于服务端权限边界。正式共享使用配套服务器。

## 快速且准确地加分

常用行为路径为：点行为 → 核对原因/分值/时间 → 确认并完成一次核验。常用项提供具体原因候选，家长确认事实后才入账，不必每次重复打字。自定义行为、原因、分值和当天补记时间在同一表单中完成。

新演示数据的四个常用项带可改写的具体原因；旧数据迁移只补空字段，不为真实历史或旧模板捏造事实。缺原因不能保存。界面显示最近一笔，便于识别是否刚记过。

提交禁连点，同一内容的超时重试保留动作 ID；已提交但响应丢失只返回既有结果，不再入账。同 ID 不同内容被拒绝。数据版本冲突保留草稿，刷新余额/价格并重新确认核验。

累计获得不因兑换减少，也不每月清零。加分是正整数，有具体原因；补记仅限今天已过去的时间。误记后的冲正/撤销政策仍未定案，本轮不擅自覆盖历史、扣累计或伪装成兑换。

## 礼品与兑换

孩子路径：查看可用积分 → 选礼品 → 核对所需分值和结果 → 申请 → 等家长确认。申请和取消都不扣分；一次保留一个活动申请，同礼品复用，换选会取消旧申请。这不限制成功兑换的月度次数或额度。

家长在待确认条上核对当前礼品与金额，完成本次核验后才扣可用积分。服务器再次检查启用状态、价格、余额、周末/月末条件；正好够分也能兑。价格变化须重新确认，重复审批不能重复扣分，累计获得保持不变。家长也可以本人先申请再确认，不要求孩子先操作。

礼品列表直接提供添加/管理。输入名称和积分即可，默认日常，需要时选周末或月底。默认启用，可以编辑价格、名称、类别和停用状态。历史保留当时名称、价格、原因与时间，不随模板变化。常用加分项也可就近维护。

本轮使用简单类别图标，**未实现拍照/上传图片**；图片不是保存礼品的门槛。不加入库存、购物车、强制心愿或履约系统。可用现有备注记录约定；“待兑现/已兑现”状态另行决定。月底暂按最后 3 个自然日，可在设置调整。

## 提醒与跨日处理

创建路径：写什么 → 今天/明天/后天或远期日期 → 可选时间/备注 → 保存并核验。远期事项选重要事件，可填提前天数。支持复制、改到明天、编辑、取消；自动每天/每周重复及整组编辑规则仍未定案。

- 未设置时间：作为当天事项展示，不凭空响铃。
- 到点与页面重开：检查已到时间的未完成、未确认事项，多条合并为一个提示，处理后再展示下一条。
- “知道了”只清提示，不代表完成；“10 分钟后”推迟提示；完成和恢复完成均不加分。
- 跨日未完成普通事项保留在今天，并显示原定日期；重要事件列表保留过去未完成事件。确认过提示也不能把未完成项变得不可访问。
- 今日的“提前准备”区仅显示进入所设提前天数范围的未完成重要事件；完整未来清单仍在重要事件中。
- 改类型/日期/时间/提前天数或切换完成状态会重置确认/稍后字段。
- 前台用真实定时器触发界面提示，声音默认关闭。无后台推送、锁屏到达保证或已验证的八小时常亮承诺。

## AI 与语音

两个模块保留共用输入框，可以说一句，也可以打字。v0.4 另在加分表单和模板管理中增加情境入口，交互与候选范围由 [成长设计](growth-design.md) 承接。当前没有配置真实模型凭证，本地整理明确标为 **指令演示**。

已实现示例：

- “明天早上七点半提醒带水杯”→ 日期、时间和标题草稿。
- “他刚才主动收好了书包，给五分”→ 具体原因和 5 分候选，不直接记账。
- “添加一个周末吃汉堡的礼品，六十分”→ 名称、60 分和周末类别候选。
- “我还有多少积分”“还差多少分能换汉堡”→ 根据真实账本和礼品条件计算回答。
- 可匹配现有事项改期，也可生成公开的兑换申请草稿。目标不唯一、缺原因或时间时追问。

写操作都回到现有表单确认与权限链路；只读数值由程序计算，模型不能凭空报余额。接口输出允许列表排除了最终兑换、验证设置和授权凭证。网络或模型失败保留输入，可继续手动操作。

服务端提供可配置 OpenAI 兼容适配，使用 `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL`，凭证不进入前端。只发送必要业务上下文和本次文字，不发送整个历史账本、密码、答案、令牌；输入对象拷贝隔离，模型适配器不能修改当前业务状态。家庭并发上限 2，每 IP 每分钟 12 次，服务端 12 秒超时、客户端 20 秒超时。未配置时不发网络请求；配置状态不等于已验证服务连通。

按键语音用 SpeechRecognition，continuous=false；识别结果只填输入草稿。不支持时保留键盘听写/打字路线。真实语音可能依赖浏览器服务和网络。本轮测试未录音、未调用真实模型，提供方边界通过模拟响应验证。

### 免触摸唤醒的评估与后续约束（未实现）

1. **点按后说**：作为当前基础入口，仍需在目标 Safari 上验证权限、听写和声音。
2. **应用常亮且前台**：有条件可行。可评估本地轻量唤醒词引擎，首次由用户开启麦克风，固定词唤醒后只采本次指令。Porcupine Web SDK 说明支持 Safari、自定义词和非英语模型，但不能据此推断旧 iPad 的稳定性、耗电和识别效果。
3. **后台、锁屏或应用退出后**：不作为网页/PWA 的可靠承诺。需另评估系统 Siri/快捷指令、原生音频或专用常电设备。App Intents 最低 iOS/iPadOS 16，因此不是这台 15.8.7 设备的直接实现路线；原生后台音频也不等于退出后自动唤醒。

后续免触摸方案应有清楚监听状态与关闭入口；优先本地识别固定词，唤醒后才上传本次语音，不持续上传家庭环境音。原始录音默认不长期保存；服务商、费用与留存需选定。网页麦克风需安全上下文与授权，普通局域网 HTTP 不能作为可用语音的依据。提醒/播报时应抑制自唤醒，没有指令时超时退出。唤醒词不用于证明家长身份。

目标设备信息已取得，剩余真机门槛是 HTTPS 录音/播音、常亮前台、锁屏/后台/恢复、连续 8 小时、1–3 米、电视和多人声音、断网恢复、误唤醒/漏唤醒/延迟/耗电发热，以及未经核验的敏感命令不写账。未达到这些证据前不启用免触摸唤醒开关。

查阅依据：

- [MDN：getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) 与 [SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)：安全上下文、授权和兼容边界。
- [Picovoice Web SDK 官方说明](https://github.com/Picovoice/porcupine/blob/master/binding/web/README.md)：Safari、WASM、自定义词、非英语模型及 AccessKey；本轮没有安装 SDK 或调用收费服务。
- [MDN：页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：后台限流和音频/实时连接例外不能当成全天候保证。
- [Apple：App Intents](https://developer.apple.com/documentation/appintents) 与 [AVAudioSession](https://developer.apple.com/documentation/avfaudio/avaudiosession)：原生系统集成及音频边界。

## 实现落点与证据

- `model.js`：状态校验、旧 v1 迁移、申请/审批、账本与提醒状态。
- `server.cjs`：真实 HTTP 权限、私有验证、限速、动作凭据、原子持久化、公共投影及助手接口。
- `app.js` / `styles.css` / `index.html`：两个模块、逐笔核验、草稿与可靠重试、手机和平板布局、前台提醒、能力说明。
- `assistant.js`：ES5 本地指令整理与模型候选规范化；`assistant-service.cjs`：外部服务适配，失败/超时与最小上下文。
- `tools/package-demo.py`：内联单 HTML，显式离线标志保证 HTTP 预览时也不访问宿主 API；源码包排除运行数据、凭证和依赖目录。
