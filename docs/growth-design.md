# v0.4 高频积分与陪伴成长

状态：**Current（累计成长、AI 与资料）**。v0.4 于 2026-11-15 完成下述历史验收。首页占屏、常用排列和近景构图由 [v0.5 满屏与直接交互](interaction-design.md) 拥有。用户再次否定旧伙伴形象与无限免费照料，已授权 [v0.6 统一加分与伙伴探险](pet-play-design.md) 替换相关条款，已完成 v0.6 验收；下文免费互动段落仅说明 v0.4/v0.5 历史实现。累计积分成长门槛、情境 AI、孩子资料和照片规则继续由本文拥有。

用户在 v0.3 交付后明确要求：兑换低频、积分高频；加分表单和常用项管理就近接入自然语言辅助；积分推动植物或动物宠物成长，形象和互动要吸引孩子；可修改孩子名称和上传头像；整体采用游戏化设计。

本文拥有高频加分优先级、情境 AI、伙伴成长体系、孩子资料及照片处理的决定，局部替换 [v0.3 核心设计](core-redesign.md) 的首页优先级与成长表现取舍；具体首页布局、行为排列和近景构图由 [v0.5 直接交互设计](interaction-design.md) 拥有。核心设计继续拥有逐笔核验、账本、兑换、提醒及语音边界。授权来自直接用户请求；没有增加外部付费美术服务、照片识别或全局家长解锁。

## 当前展示边界

[v0.7自解释界面](self-explanatory-ui.md) 替换成长、AI与资料页面的系统说明段落及教学文案；成长图鉴、字段、状态、具体业务回答和保存前核验继续保留。本文仍拥有累计成长、AI候选和照片规则。

## 问题与结果

v0.3 让高频加分与低频兑换占据相近面积，家长需要离开表单寻找自然语言入口。孩子主要看到数字，缺少一个能回应当下进步、显示长期积累的形象。

当前保留“积分 / 提醒”两个一级模块。积分首页优先呈现孩子资料、可用积分、加分、常用行为与成长伙伴；兑换移入次要面板，待审批申请仍能从首页直达。伙伴嵌在积分页，不增加独立的成长一级模块。

## 当前决定

### 首页与情境录入

- v0.4 的固定场景高度、手机纵向滚动和完整行为铺排已撤回。当前首页占屏、常用排序、全部选择入口与角色近景的决定及验收统一见 [直接交互设计](interaction-design.md)。
- 加分表单内的“AI 帮我填”提示“因为什么，加多少分？”。“自己收好了书包，加5分”会整理为同一张表单中的行为、分值与具体原因；用户可修改，点击确认并通过本次家长核验才记账。
- 常用项列表与编辑表单均有自然语言辅助，支持新增、改名、改分、修改预设原因、停用和启用。只生成模板草稿，不给孩子加分，也不修改过去的记录。
- 人工输入、取消、换场景或进入核验后，迟到的整理结果不能覆盖当前内容。服务失败时保留输入，仍可手动保存。
- 模板草稿取消后保留原描述；真实保存成功返回列表后，清空已完成的描述并显示列表已更新。没有后台请求时不残留“正在整理”。
- 当前使用明确标注的本地“指令演示”。OpenAI 兼容服务适配已实现，但未配置真实外部模型凭证；不能把本地规则或模拟上游通过说成外部模型已联通。

### 成长体系

**累计获得 1 积分 = 1 成长值。** 可用积分用于礼品兑换和道具购买，成长只从累计获得账本派生，没有独立可写的经验余额。消费、照料、更换物种和伙伴改名都不能改变成长。

| 累计成长值 | 阶段 |
| ---: | ---: |
| 0 | 1 |
| 30 | 2 |
| 100 | 3 |
| 250 | 4 |
| 500 | 5 |

阶段造型与名称由 [v0.6 伙伴探险](pet-play-design.md) 拥有；界面读取 `FamilyModel.growthStages(kind)`，不再沿用旧植物形态名称。

500 时是第 5 阶段、0 颗成长星。此后每增加 250 成长值增一颗星：750 时第 6 级、1 星，1000 时第 7 级、2 星，形态保持第五阶段。`previousAt` / `nextAt` 表示当前阶段或星段的边界，进度在该区间内计算；在最大安全整数边界封顶，不溢出。

示例账本累计 128 分，映射第三阶段：上界 250，还差 122，本阶段进度 28/150。旧账本直接按全部累计积分映射，不重置历史，不伪造过去的互动记录。

每次真正加分成功都会有伙伴回应；跨阶段或新增成长星时显示升级信息。“成长说明”展示五阶段实物形象与到达印记。没有排行榜、抽奖、连签损失、饥饿生病或忘记照顾的惩罚。

### 形象与免费互动（v0.4/v0.5 历史设计）

以下两段保存旧取舍；当前形象、公开照料与资源消耗由 [v0.6 伙伴探险](pet-play-design.md) 拥有。

两种伙伴各有五个原创 SVG 形态，与小院、眼神、表情及互动道具一起绘制。没有 WebGL、视频或外部图像依赖。植物支持摸叶子、浇水、晒太阳；水豚支持摸摸、喂点心、一起玩，直接点角色也能互动。

互动是无需验证的即时回应，不扣积分、不刷成长、不写计次账本。换伙伴与伙伴昵称也公开可操作，昵称 1–40 字。减少动态效果时仍保留静态表情、道具和文字；成长说明和选择预览使用静态绘制。声音沿用原设置，默认关闭。

### 孩子资料与照片

点击首页孩子头像/名称可编辑。孩子名称为 1–40 字，资料保存和头像移除都需逐笔家长核验。

选择 JPEG、PNG、WebP，客户端限制原图不超过 8 MiB、1600 万像素。浏览器在本机解码、居中裁剪为方形，缩到 192×192 后重新编码为 JPEG。保存前显示预览；取消不写状态。原始文件和元数据不发送到服务器或模型。

最终头像 data URL 限 160000 字符，接口默认请求体上限为 256 KiB。领域模型与服务端检查 MIME、Base64 和基本文件标识，拒绝 SVG、远程 URL、错误编码、标识不符及超限输入；这不是服务端完整图片解码。

压缩头像随家庭状态保存在自建服务器，并同步至同一家庭的设备；离线版只在本机保存。服务器向助手传递状态前即删除头像，适配器的最小上下文也不含照片。实际文件选择、裁剪、保存、刷新、移除和出站请求隔离使用合成照片验证，没有使用真实儿童照片。

## 数据与接口合约

- 状态新增 `childAvatar: '' | data URL`、`pet: {kind:'plant'|'capybara', name:string}`；旧数据默认空头像与 plant/芽芽。迁移保留已有名称、账本、申请、核验凭据和幂等收据。
- `profile.update {childName,childAvatar}` 是家长操作，只修改孩子资料。
- `pet.configure {kind,name}` 是公开外观操作，不修改账本或孩子资料。
- `FamilyModel.growth(state)` 返回 `{xp,stage,level,stageName,previousAt,nextAt,remaining,progress,stars}`。stage 为 1–5，progress 为 0–1，500 后 level/stars 继续增加；种类不改变门槛。
- `FamilyPet.render({kind,stage,name,reaction,reducedMotion})` 返回 SVG，外部文字转义；[角色绘制](../pet.js)与[角色样式](../pet.css)单独拥有美术实现，主界面不另画一套。
- `POST /api/assistant` 接收可选 `{context:'general'|'points'|'pointItems',targetId?}`。服务调用 `interpret(text,state,now,{context,targetId})`；旧三参调用默认 general。
- 管理候选为 `pointItem.save {payload:{item:{id?,name?,points?,reason?,enabled?}}}`。points 情境只允许一次加分草稿，pointItems 情境只允许模板草稿；目标不明确时澄清，不默认批量写入。省略字段保留原模板值。
- AI 草稿不能生成核验授权；领域校验和原逐笔授权流程保持有效。完整动作及版本绑定授权，冲突后重新核对和验证。

## 替代方案与后果

- 按可用积分成长会在兑换时退步，因此使用累计获得积分。成长与消费分离，但不引入第二种可消费货币。
- 按喂养次数或每日连签成长会鼓励刷互动、增加日常负担，因此互动只负责回应。家长仍决定具体行为应获得多少分。
- 只放全局 AI 入口增加录入跳转，因此保留共用入口并在两个高频表单内提供情境帮助；这也要求独立处理草稿与异步返回。
- 只有一张吉祥物图片缺少成长差异，因此实现两种五阶段矢量形态。500 后继续以成长星延展，不无止境新增形态。
- 手机半宽角色的问题在 v0.4 通过全宽场景缓解，但用户实际反馈证明本体仍太小且不能接受首页滚动。此项取舍已被 v0.5 替换，角色本体尺寸与主区无滚动分别接受检查。
- 原图上传与外部图像处理增加体积和数据暴露，因此在本机只生成小头像。原图格式/尺寸限制及居中裁剪是当前明确的取舍。

## 已验证的验收义务

详细结果、截图、分组历史及边界见 [v0.4 验收记录](../artifacts/v4-verification.md)。团队累计 146 项为 74 模型/接口、20 助手、8 角色、8 客户端、36 新版浏览器检查；按变更路径定向复测累计，不是一个命令的一次执行。角色 140 参数组合属于 8 项中的覆盖矩阵，不再重复加总。

1. 迁移、全部成长门槛两侧、750 首星及最大安全整数边界通过模型/接口检查；实际浏览器逐笔加分跨越全部阶段，并完成兑换验证不退级。
2. 两种伙伴十阶段与各三种互动均实际渲染；减少动态静态反馈通过，图像经 Lead、UI、美术与 QA 分工复看。
3. 加分同表回填、确认前账本不变、逐笔核验、手动修改和迟到结果隔离通过实际操作检查。
4. 模板的新增/改名/改分/预设原因/停用/启用、保存/取消/再次整理通过，累计积分与历史记录不变。
5. 合成 PNG 实际居中裁剪到 192×192 JPEG、元数据去除、预览/取消/PIN 保存/刷新/删除通过；真实适配器到本机模拟上游的请求不含头像或核验信息。
6. 五种视口无横向溢出，1024×768 首屏关键元素边界与命中可用；8 项客户端同步/冲突/重试回归通过。未声称重跑 v0.3 全部提醒生命周期测试。
7. 最终单 HTML 包精确内联四份脚本与两份样式；file 与 HTTP 托管两种方式都验证本机模式、持久化与零 API 请求。最终 HTML 的字节数和 SHA256 已写入验收记录。

尚未验证：iPad mini 4 / iPadOS 15.8.7 Safari 实机、软键盘、真实麦克风/听音、八小时常亮与休眠恢复，以及真实外部大模型。单次点按听写保留；免触摸唤醒未实现。离线文件不是跨设备共享服务；手机与 iPad 共享需运行 [README](../README.md) 说明的服务器。
