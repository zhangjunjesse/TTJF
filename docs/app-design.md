# 小小向前：App 式交互决策（v0.2）

状态：v0.2 实现及下述技术验证已完成，但用户随后否定其产品定位与核心流程；后续产品设计由 [积分与提醒核心重设计提案](core-redesign.md) 承接。新提案尚未实现，旧验证不能证明新权限与新流程成立。类型：Feature / Replace。日期：2026-11-14。

本决策取代 [v0.1 网站式布局](demo-design.md) 的界面组织；业务规则仍由 [家庭看板需求文档](家庭看板需求文档.md) 持有。替换授权来自用户明确反馈：“要做成 app 式的……完全按照 web 网站设计……不行”。

## 问题

ADHD 家长和 8 岁孩子需要低负担、能马上行动的工具。旧版纵向网页、介绍文案和多块统计卡片迫使人反复浏览；在常亮 iPad 和手机上，这种信息组织与用户期待的 App 不一致。

## 采用的交互

- 固定视口的 App 外壳：简短顶部栏、独立主区域和四项底部导航。无网站侧栏、面包屑、宣传横幅或页脚。没有伪造手机外框、系统状态栏与电量。
- 首页是一屏任务舞台：今天/明天/后天、一个主要安排、陪伴插画、大完成按钮。手机用“接下来”条目展开完整清单；iPad 横屏可同时看到清单。重要日子独立保留。
- 主操作优先于装饰。320×568 收起插画和心愿摘要；完成按钮、安排入口和重要日子仍保留。长标题最多两行，完整文字可在“只看这一件”与编辑中查看。
- 新建、加分、兑换和编辑从底部展开。字段区滚动、操作区固定，背景保留；关闭、Escape 和拖动把手下拉可以收起。嵌套编辑保存或返回后回到上层清单。
- 家长页使用“记一件事 / 记闪光 / 说出来”三个快捷入口与分组列表。行为、奖励、历史和设置按需展开，不再堆成长管理页面。
- 主按钮手机至少 56px、iPad 至少 64px，其余触控目标以 48px 为基线。输入至少 16px，使用原生日期和时间控件。visualViewport 变化调整应用高度；面板内保留键盘焦点，系统减少动态设置生效。
- 普通状态提示不拦截触摸，只有“撤销”按钮可交互；打开面板清除上一条无关提示，减少遮挡。
- 标准 Web App Manifest、192/512 图标、iOS standalone 元信息支持添加到主屏幕。实现是网页 App Demo，没有提供原生 IPA/APK、应用商店分发或后台服务。

## 保留的规则和技术边界

完成任务不自动加分。加分需要具体原因，支持现在或今天稍早。累计积分一直保留；可用积分等于累计减去兑换。兑换需符合奖励状态、日期与余额；远端数据变化后要重新确认。没有月度额度/次数限制、排名、扣分或强制倒计时。

行为与奖励停用保留历史快照。近期待办只覆盖今天、明天、后天，未来的重要日子独立存在；事项可软删除和恢复。月末暂按最后 3 个自然日，界面可选 1/3/7 天（模型允许 1–31）；分类日期条件独立，不把 Demo 假设当作最终业务决策。

经典 ES5 脚本和不依赖框架/CDN的样式；图片与原创 WAV 都在本地。字体使用系统字体。语音仅由用户主动开启，先得到可编辑草稿；缺少 API 时使用键盘听写。声音默认关闭。

HTTP 模式用 Node 原生服务器、JSON 原子持久化、版本检查和动作 ID 幂等；5 秒轮询。首次连接成功前不允许共享写入，迟到的 GET 不回退状态，网络不确定时重试保留同一个动作 ID。单文件强制 localStorage 模式；两种模式不伪装为同一种保存。

## 替代方向与取舍

- 仅隐藏旧侧栏：仍保留长网页与整页表单，不能解决操作路径问题，因此替换视图结构。
- 原生 iPad/iPhone 客户端：系统能力更强，但需要签名、构建与分发。本轮保留无需额外安装工具即可评估的网页 App，主屏入口提供独立窗口体验。
- 把所有设置铺在主屏：减少一次点击，却增加儿童的无关信息；改为清单和操作面板。
- iPad 与手机完全相同排布：会浪费横屏空间或挤压小屏操作，保留相同导航和动作，但以可见空间决定清单是否展开。

## 已知范围

未在用户的旧 iPad 真机验证，尤其是 Safari 版本、软键盘、主屏安装与系统常亮权限；现代 Edge 视口模拟不能代替这些实机能力。常亮、全屏和语音都进行能力检测。前台按时提醒，没有锁屏/后台通知和漏提醒补发。

Demo 没有账户认证，家长入口是操作分工。未部署到用户的公网服务器。正式上线需要认证、HTTPS、备份和设备验证。交互设计旨在降低认知负担，不宣称治疗 ADHD。
